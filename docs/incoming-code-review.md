## 双击exe为何一闪而过

原包exe无参数时，stdout为空，stderr为 `Usage: rocketperf run CASE.ini (or --help / --version)`，退出码2。Windows为控制台程序打开的临时窗口随其退出关闭。带正确命令参数可以运行；在只保留Windows系统目录的PATH中也能运行。实际PE导入仅为系统DLL，本次没有发现因漏带编译器运行库导致的启动失败。

同学 `.bat` 的 `pause`和两级菜单解决了交互入口问题。它依赖GBK/936，重复运行覆盖同名结果，在标准输入EOF时继续循环；交接把“任何Windows都能直接跑”和“自动化输入可用”说得过宽。本次验证的是本机936代码页及逐提示输入，不声称所有系统/双击桌面路径都已模拟。

当前工程已经在 `src/cli/main.c`和`interactive.c`实现C内置菜单：真实控制台无参数进入交互，重定向无参数仍返回语法错误；显式 `interactive`支持EOF退出。新运行包提供ASCII的 `rocketperf-run.bat`，只定位包目录并调用这一个C菜单，选择8再选1–5运行车辆研究情景。它不参与计算、不调用Python，也不依赖GBK脚本正文。正常结束退出，异常退出保留诊断。

## 与当前模型如何对接

| 比较项 | 同学 `staged_thermal_cycle_v1` | 当前 `adiabatic_single_shaft_cycle_v1` |
|---|---|---|
| 温度/热边界 | 指定主室和预燃室温度，TP求组分，倒算两项所需Q | 两处Q=0，从入口与回流库存求HP温度 |
| 支路与轴功 | 给定涡轮出口压力，按比功反算支路；并非全部氧化剂进涡轮 | 全氧化剂富氧补燃，按已知预燃流量/轴功求涡轮出口压力 |
| 主室回流 | 回流焓进入热量账，主室组分由总体CH4/O2及给定TP得到 | 回流焓及实际C/H/O库存和新鲜燃料混合求主室HP |
| 燃料身份 | 固定甲烷/氧气，煤油密度可被声明输入 | 甲烷单相液态表或独立RP-1指定替代物身份 |
| 输出身份 | `cycle prescribed`下增加开关和独立model | `cycle adiabatic`，独立输入/结果/来源字段 |

两者物理问题不同，本次保留同学原件及研究输出，不用它覆盖当前生产循环实现。给定温度的补燃教学计账可作为对照资料；最终计算演示采用已经登记/验证的绝热研究入口。两种路线都没有真实泵图谱、冷却、凝聚相、起动/寿命或整机实验标定。
