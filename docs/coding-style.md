# C代码撰写规范

本文写给修改 `src/` 或 `include/rocketperf/` 的人。约定提炼自现有代码，不是另起的一套规则；新代码照此写，旧代码在实质性修改时对齐。模块边界与依赖的机器可查版本在 `project/modules.json`，本文只解释写法。

## 分层

- 计算核心（core/nozzle/thermo/cycle）不执行文件、控制台、网络和环境操作，不分配堆内存，不使用全局可变状态。格式化错误文本（`snprintf` 写入调用方缓冲）不算 I/O。
- adapters 承接文件格式、JSON 输出和 Windows 路径；cli 只做命令分派、参数解析和调用顺序。解析规则不进物理求解函数。
- 新增 `#include` 前先核对模块登记的允许依赖；质量检查会拒绝越界引用和未登记源码。

## 命名

- 函数 `rp_动词_对象`，类型 `Rp` 前缀加驼峰，宏 `RP_` 前缀加全大写；CLI 私有函数用 `rp_cli_` 前缀。
- 物理量字段以单位结尾：`_pa`、`_k`、`_m2`、`_j_per_kg`、`_kg_per_s`；无量纲量写全称，如 `oxidizer_fuel_mass_ratio`。
- 同一物理量全项目一个名字。压力统一 Pa、比冲统一 s；MPa 或 m·s⁻¹ 只出现在用户文档与用法串，不进入结构体。

## 接口

- 输入参数为 `const` 指针；结果经单独的输出指针返回。失败不写输出：先算进局部结构体，成功后一次提交（事务式输出）。
- 数值策略（容差、迭代预算、温度界）由 options 结构体传入；传 `NULL` 用默认值，不引入全局配置。
- 新物理模型用新 ID 和新接口，不悄悄改变旧 ID 的含义、输入单位或失败语义。

## 错误

- 每次调用检查 `RpStatus`；给人读的详情放 `RpError`，消息写明失败原因与数值范围。
- 非有限数、越域、未知标识、预算耗尽一律显式失败，不填零、不截断、不自动回退。
- CLI 退出码：0 成功或帮助；2 用法错误；3 文件/格式/输出错误；4 模型/求解拒绝。失败时 stdout 保持为空。

## 注释

- 契约写在头文件声明前：适用域、单位与焓基准、失败语义、与其他模型的关系。范例见 `include/rocketperf/combustion.h` 各段块注释。
- `.c` 文件不复述头文件注释，只写实现里非显然的约束：位置参数布局、表驱动字段的 offset 链、阈值取值原因。
- 不写日期、作者、变更日志和“此函数用于”式复述；这些信息在 Git、taskshot 和文档里。
- 注释用英文，与既有源码一致；面向组员的解释放文档。

## 惯用模式

- 表驱动解析：字段名数组配 `offsetof` 偏移数组，嵌套结构体用宏拼接偏移，见 `src/adapters/propellant_case.c` 与 `cycle_case.c`。
- 求解器注入：夹逼二分求根用函数指针加只读 context，物理方程不进入数值模块，见 `src/core/root.c`。
- JSON 数值用 `%.17g` 输出保证 double 往返；输出函数返回成功标志，调用方串联写入、统一处理失败。

## 格式与警告

- 4 空格缩进、UTF-8、LF；单语句块写在一行 `{ ... }` 是既有风格，不必拆开。
- GCC 开 `-Wall -Wextra -Wpedantic -Werror -Wconversion -Wshadow -Wstrict-prototypes -Wmissing-prototypes`；修问题，不压制警告。MinGW 泛型 `isfinite` 的窄化诊断用 `rp_isfinite`（double 有序比较）解决，保留 `-Wconversion`。

## 测试

- 每个拒绝路径配负向测试：错误单位、非有限数、越域、未知 ID、篡改输出。
- 参考值来自解析推导或独立软件，不运行被测程序生成期望值。
- 改失败或解析行为先补测试再改实现；`python tools/quality.py` 是唯一验收通道。
