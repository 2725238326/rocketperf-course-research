# 这次大作业要交什么

## 一句话

调查朱雀三号和长征十号乙的动力系统，用一套能在 Windows 上运行的 C 程序计算发动机性能，再用计算结果分析优缺点和一项改进方案。

## 四项最终交付

1. **源代码**：核心计算使用 C；输入、计算、结果输出能从头运行。
2. **Windows 发布版**：解压后能运行的程序、算例和说明，不要求 WSL。
3. **研究报告**：回答查到了什么、采用了什么参数、怎么算、结果是否可信、改进是否值得。
4. **展示 PPT**：10 分钟以内，演示一条已经复现过的计算路径。

## 当前先做的两部分

PPT、报告和发布打包暂时不作为当前工作面。先把下面两部分做实：

### A. 两型动力系统资料和参数

交付一张可核对的资料表：对象、级段、版本/批次、推进剂、发动机数量、工作方案、公开能力、来源位置、单位、工况和未知字段。它的目标不是把表填满，而是知道哪些参数真的能进入计算。

### B. Windows 性能计算

交付一条从参数文件到 C 结果的计算路径：输入、公式、C 源码、结果、误差检查和适用范围都能复现。先保留已经通过测试的理想喷管基线，再根据 A 部分的可用数据决定是否加入温变热物性和更高层模型。

只有 A、B 的证据和结果稳定后，才进入报告、PPT和发布整理。

## 报告最终要回答的三个问题

### 1. 两型动力系统是什么

按一级、二级、飞行批次或产品版本整理推进剂、发动机数量、循环、回收/重复使用相关工作和已公开能力。每个数字都标明来源、工况和边界；找不到的参数写“未知”。

### 2. 性能怎么算

先把公开参数或明确的研究假设送入 C 程序，计算出口状态、流量、推力、推力系数和比冲等。结果必须带单位、模型假设和适用范围。当前已经有的是定比热理想喷管基线，它用于验证程序和说明趋势，不能冒充真实发动机结果。

### 3. 哪些地方值得改

选一个可以计算、能说明代价的方向。例如喷管面积比与环境压力的权衡，或者支路排气对整机性能的影响。报告要同时写收益、代价、输入不确定性和不能判断的部分。

## 我们项目的实际优势

- **边界诚实**：不把产品宣传数字、不同批次参数和教学空气参数混成一个“真实发动机模型”。
- **结果可复现**：Windows 下从算例文件到 JSON 结果，保存输入、程序版本和运行记录。
- **核心符合要求**：物理计算放在 C17；Python 只负责构建、检查、归档和画图。
- **有验证**：先用解析喷管关系、守恒关系和错误输入测试程序，再做研究计算。
- **能解释限制**：参数缺失时不编造，而是说明它会影响哪一项结论，并用条件性情景继续研究。
- **交付路线短**：不做 GUI、CFD、有限元或整库重写，把时间放在两型资料、性能计算和改进分析上。

## Windows 边界

日常开发只需要 Windows、Python、MinGW GCC 和可选的 CMake。WSL、`libasan`、`libubsan` 不属于发布版，也不影响普通构建。sanitizer 只是额外检查，本项目不以它作为交付前置条件。

## 不做什么

本次不做有限元、三维 CFD、完整真实流体数据库、完整发动机瞬态、真实回收寿命预测或 GUI。它们可以在报告限制中说明，但不能挤掉课程要求的资料、C 计算、改进分析和四项提交物。
