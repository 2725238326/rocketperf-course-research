# 首版模型设计契约

版本：DES-001 v0.1；设计日期：2026-10-02

本文件把作业问题、研究证据、数据角色、C模块、输出和验证连接起来。它是实现契约，不代表高级热化学和循环模块已经完成。

## 1. 交付问题

当前S1问题：用明确输入研究面积比与环境压力的性能权衡，并说明不能外推的结论。这只是大作业中的一个算例；两型动力系统工作方案、燃烧工质性能及改进研究仍需后续数据和模型。

副问题：在具备热边界和守恒验证后，节流时质量流量、喷注压降、冷却剂焓升和喷管分离风险如何共同影响稳态性能？

对象层次：

- `ZQ-3 遥一`和`CZ-10B 首飞`只作为构型/推进剂/回收背景事实，不把缺失字段假装补齐。
- `ZQ-3 当前产品页`和`CZ-10B 发动机家族`只能构成候选或架构情景，必须带独立假设编号。
- `synthetic_mach2`是代码回归基准，不属于任何真实型号。

## 3. 模块边界

```text
CLI/input -> case/schema -> thermo -> nozzle -> cycle -> study -> result JSON
                         |         |          |         |
                     data/参数   L1状态    守恒残差   扫描/敏感性
```

- `core`：SI单位结构、有限数检查、二分/阻尼Newton/LU、残差和错误码。
- `thermo`：NASA9多项式、物种元素计数、形成焓、受限平衡；不直接依赖Python对象。
- `nozzle`：L0等熵与L1温变冻结喷管；输入输出显式标记平衡/冻结和模型ID。
- `cycle`：L2质量、能量和轴功率控制体；不实现起动瞬态、控制器或寿命。
- `study`：批量工况、情景和敏感性；只读取已冻结输入，不在扫描中偷偷调参。
- `cli`：严格输入、结果JSON、运行manifest；不承载物理公式。

上图是扩展设计，不是现状依赖图。当前有`core/thermo/nozzle/adapters/cli`及工程工具；受限TP/HP和温变冻结喷管已实现，循环尚未实现。扫描C函数在`nozzle`，运行manifest由Python工具保存。实际源码和依赖以`project/modules.json`及[架构图](architecture/README.md)为准。

第三方项目只在`tools/`用于对照：NASA CEA作为热化学参考，Pyskyfire/RocketCycles作为模块组织参考。不要让Python/Fortran调用链穿透C业务核心。

## 4. 数据契约

每个字段必须有：对象/批次、原值和SI值、单位、工况、控制体、`data_role`、来源、适用范围和用途。

`data_role`只有四类：

- `fact`：原始来源直接支持的事实；如ZQ-3遥一 9×TQ-12A。
- `derived`：由事实和明确公式换算；如吨力到N。
- `synthetic_benchmark`：人为构造且有独立解析参考的教学输入。
- `assumption`：为研究情景选取的范围或点值，必须有理由、敏感性和模型ID。

`data/parameters/baseline.json`只保存前三类和缺失清单；真实型号缺失字段不能被求解器读取。假设必须以独立记录进入研究算例，并在结果JSON显示假设编号。

## 5. 数值和失败语义

- L0面积比方程使用夹逼二分；输入越界、背压超出模型边界、非有限值和预算耗尽返回明确错误。
- L1平衡先做定温定压，再做定压绝热焓平衡；正量约束、元素残差、温区越界和不收敛必须失败，不得返回“看起来合理”的结果。
- L2对质量、能量、轴功率残差设置绝对和归一化容差；支路为零、排气全并入、排气全外排都是必须测试的极限。
- 单点失败不覆盖结果；扫描逐点记录状态，参数错误清零点数且不写点数组。数值失败不产生成功`result.json`，运行manifest保留原因和输入哈希。

## 6. 研究算例

### S1_area_ratio_ambient

- `C0_mach2`：当前已验证教学算例，作为每次改动的回归门槛。
- `S1_area_ratio_ambient`：固定入口状态，扫描面积比和环境压力；主选题。
- `S2_throttle_cooling_condition`：在明确的集总热拾取假设下扫描节流比；只有L2通过后启用。
- `S3_architecture_context`：把ZQ-3/CZ-10B公开构型作为背景标签，不输出虚假的真实发动机绝对性能。
- `S4_thermochemistry_compare`：L0/L1相同输入对照，报告模型差异来源，不把差异全归为硬件损失。

## 7. 结果报告必须回答

1. 这组输入属于哪个对象、批次、模型和假设包？
2. 推力是主室边界还是整机边界？质量流量是否包含支路？
3. 面积比和环境压力改变带来的收益是什么，代价和越界区域是什么？
4. 结果由代码误差、模型差异还是数据/假设不确定性主导？
5. 哪些结论只是趋势，哪些有独立参考，哪些尚不能判断？

报告禁止：用产品目标替代飞行实测；用同系列参数拼造子型；用外部软件输出伪装成C核心结果；用稳态曲线证明深度节流、起动可靠性或重复使用寿命。

## 8. 实施顺序

1. 保留L0解析基准，维护已实现的S1入口与输出检查。
2. 实现NASA9物性并完成独立校核，再进入L1。
3. 明确主室/整机控制体和支路边界，完成L2守恒，再考虑S2。
4. 结果、图表和报告只引用已通过验证的模型ID。
5. 若L1/L2不能按计划通过验证，记录问题并向用户确认范围调整；不以外部求解器补齐缺失结果。

## 9. 当前待确认事项

- NASA9物种子集、煤油替代物和数据库版本需要在实现任务中锁定。
- 真实型号研究是否采用任何发动机性能点，取决于后续是否获得字段级原始证据；否则只做架构情景。
- 节流/冷却副题是否进入最终展示，取决于L2热边界和守恒测试是否通过。
