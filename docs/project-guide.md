# Rocketperf 项目解读

本项目为朱雀三号与长征十号乙动力系统课程研究提供资料、C17性能计算和条件性改进分析。现有程序在Windows上直接运行，能够计算燃烧室、喷管和给定热状态的循环计账。真实型号性能卡尚不完整，报告中的方法算例须保留其输入假设。

本文说明研究对象、数据口径、C17计算方法、模块职责、运行编译和验证方式。任务与版本实况由完整仓库的worknow和doctor维护。

## 1 作业与产物

老师要求调查两型动力系统工作方案和工作能力，用基本理论含计算分析性能，进一步含计算研究优缺点和改进设计。核心计算使用C语言，最终提交源码、发布版、报告和PPT。

| 课程问题 | 项目中的答案位置 | 目前能交付什么 |
|---|---|---|
| 两型各级采用什么方案 | 资料台账、四级段映射、组员参数审阅 | 分版本的构型/能力事实和缺失参数 |
| 性能如何计算 | C17物性、HP、冻结喷管、循环模块 | 可运行程序、明确输入、SI结果和参考对照 |
| 怎样比较与改进 | 喷管/背压、支路排气、入口焓响应 | 同条件收益、几何代价和模型限制 |

采用零维燃烧室、准一维喷管和稳态部件模型。课程没有要求有限元或三维CFD；现有模型不能给出结构强度、起动瞬态、冷却寿命或真实回收轨迹。

## 2 数据如何进入计算

![研究流程](architecture/business.svg)

四个对象为朱雀三号遥一一级/二级、长征十号乙首飞一级/二级。原文事实带对象、版本、日期、单位和工况；派生量附公式；研究输入单列假设；未知字段保留空值。

例如TQ-12A产品页给出84.6 t、293 s和混合比2.9。产品栏目不能直接成为遥一单机工作点；混合比还未明确主室/整机口径。2023年12B/15B目标参数不能补进遥一A型性能卡。140吨级开式甲烷试验产品有原文，但完整装机身份仍须桥接。

计算前先确定模型ID和输入边界。CH4/O2、固定RP-1与国产煤油批次分别记名；九物种气相方法不预测凝聚碳。喉面积决定绝对流量/推力尺度，没有尺度时不能为了得到推力数字任意填值。由公开推力反算的参数属于校准，不能再用同一推力作为独立验证。

参数档案与研究证据在完整私有仓库保留。轻量源码包只携带编译所需固定数据、C测试及来源许可；不需要原始课件或网页才能运行计算。

## 3 一次计算的业务流程

```text
用户参数或严格算例文件
  -> CLI语法检查
  -> 具名模型接口与输入域检查
  -> 固定反应物/连续液体查表生成焓和元素库存
  -> HP燃烧室状态
  -> 冻结喷管和几何性能
  -> 成功JSON或明确失败诊断
```

气态、指定液态锚点和连续液体入口有不同接口。连续液体查询返回密度与化学焓，HP只使用已对齐的化学焓和元素库存；入口压力只选择物性状态，并未求贮箱、泵和喷注压差。

给定热状态循环是另一条路径：恒密度泵估算轴功，冻结涡轮提供轴功，按预算求支路流量，分别计算主/支喷管，再按总消耗和总推力计整机口径。热状态为输入，所需热交换由能量边界倒算；它尚不构成绝热完整发动机循环。非零回流明确拒绝。

## 4 C模块和设计

![计算架构](architecture/components.svg)

| 目录 | 职责 | 典型接口或文件 |
|---|---|---|
| src/core | 状态码、有限数、夹逼二分 | status.c、root.c；RpStatus/RpError |
| src/thermo | NASA9、混合物、TP/HP、具名反应物、单相液体表 | equilibrium.c、reactants.c、liquid_feed.c |
| src/nozzle | 定比热/温变冻结喷管、固定喉面积 | ideal.c、frozen.c、liquid.c |
| src/cycle | 泵/涡轮、外排支路、同条件扫描 | components.c、prescribed.c、study.c |
| src/adapters | INI、JSON、Windows UTF-8路径 | case_file.c、cycle_case.c、platform.c |
| src/cli | 用户参数、调用顺序和报告 | main.c |
| include/rocketperf | 公共输入、输出和函数声明 | combustion.h、frozen_nozzle.h、cycle.h |

核心通过值类型结构体传SI字段，无文件/网络/控制台I/O、堆分配或全局可变状态。它可以被CLI、单元测试或其他C调用方复用。格式化错误文字不等于执行控制台I/O。

失败前先写局部结果，成功后一次提交到调用方输出。输入是const，数值策略由容差/迭代预算结构体传入。新模型用独立ID，不悄悄改变旧甲烷或定比热接口含义。src/adapters和CLI承担格式与路径操作，避免把解析规则塞进物理求解。

模块登记在project/modules.json，GCC入口与CMake读取同一生产C文件清单。新增源码应登记所有权和允许依赖，再补公式/失败契约、测试和架构图。文件树用于导航，图用于解释计算关系。

## 5 热化学如何求解

NASA九系数表示各物种的cp、h和s，包含形成焓贡献，并严格使用各温区。当前平衡产物为H2、O2、H2O、CO、CO2、CH4、H、O、OH九种中性理想气体。

TP内核在定温定压下满足元素库存和化学平衡，以元素势方程求解。小矩阵使用带主元消元，外层采用阻尼Newton、残差缩放与线搜索。非正量、病态矩阵、预算耗尽或残差不合格均返回失败。

HP在1000–6000 K内夹逼并二分，求`h_products(T,p)=h_feed`，Q=0。元素库存须表示同一化学质量基准的一公斤混合物；不能只归一化元素比例而丢掉质量尺度。固定反应物已有形成贡献，不能重复加形成焓或减汽化潜热。

RP-1使用固定CEA的C1H1.95元素计账、298.15 K指定焓与O2(L)90.170 K。公共方法限定产品10 MPa、O/F=2.2–4.0，拒绝任意液体温度、未知燃料/数据集或焓覆盖。C1H1.95是计账单位，不代表某个实际分子或中国燃料批次。

连续CH4/O2表由固定单相参考离线生成，C运行只双线性查表。域为CH4 100–140 K、O2 80–110 K、压力1–20 MPa；两相、超域和临界邻域不能自动外推。EOS密度质量口径与CEA化学焓质量口径分别返回，不能无声明混算。

## 6 喷管与循环量的含义

冻结喷管保持燃烧室组分，以温变h/s求声速喉部、超声速出口和阻塞质量通量。它包含压力推力项，当前只支持匹配/欠膨胀；高背压返回out_of_domain，并不等于证明真实流动已分离。

核心关系为：`mdot=Pc*At/c*`；`F=mdot*ve+(pe-pa)*Ae`；`Isp_s=F/(mdot*g0)`，`g0=9.80665 m/s²`。面积比为Ae/At，比冲若来源使用m/s须先确认有效速度口径再换算秒，不能与秒制直接比较。

循环总流量包含排出支路，整机推力按主喷管和轴向支路贡献相加。支路排气投影改善整机计账性能，不代表喷管延伸段混合或补燃回流已经求解。循环扫描给定流量后重定尺寸；单喷管固定At则由通量求流量，两个算例不能串成同一真实硬件调节曲线。

## 7 Windows直接运行

成对研究用一条命令保持两方法共同的压力、喉面积、面积比和背压，直接返回两路状态与CH4−RP-1差值：`./rocketperf.exe study propellants 2.6 2.6 10 0`。入口CH4=120 K、O2=100 K和两路查表压力10 MPa、固定RP-1=298.15 K/O2(L)90.170 K在JSON中明确记录；该命令固定Pc=10 MPa、At=0.01 m²。任一路失败都拒绝整个成对结果。

交接时可改用算例文件：`./rocketperf.exe study propellants --case cases/research/propellant_comparison.ini`。它把共同几何和两路混合比存成一份严格输入，字段核对与错误协议见[算例文件](propellant-case-format.md)；修改C代码的命名、注释和警告纪律见[代码规范](coding-style.md)。

共同O/F=2.6、A10真空时甲烷方法比冲高13.8534 s，但推力低343.5653 N。固定喉面积下c*增大使流量降低，比冲不能单独决定绝对推力。[同条件研究](propellant-method-comparison.md)记录三组O/F情景、喷管几何/背压和独立软件参考。

解压Windows包后进入包目录，用PowerShell执行。运行程序只需要Windows系统运行库，无需Python、CEA、Fortran、Grok或编译器。

```powershell
./rocketperf.exe --version
./rocketperf.exe run cases/benchmarks/air_mach2_vacuum.ini
./rocketperf.exe combustion frozen-rp1 cea-v3.3.4-rp1-o2l-assigned-v1 liquid RP-1 'O2(L)' 10000000 2.6 298.15 90.170 10 0 0.01
./rocketperf.exe cycle prescribed cases/benchmarks/prescribed_cycle.ini
```

RP-1样例得到燃温约3724.0068 K、c*1760.6575 m/s、流量56.79696 kg/s、推力172.98471 kN、比冲310.57173 s。它对应固定输入/产物集和真空单喷管；不是长十乙实测性能。

连续甲烷入口例为Pc=10 MPa、At=0.01 m²、A10、O/F=3.4、CH4=120 K、O2=100 K，两路查表压力10 MPa：燃温约3602.756 K、c*1811.000 m/s、推力173.72121 kN、比冲320.81194 s。与上述RP-1入口的混合比/反应物状态不同，不能用两个数字直接给发动机或推进剂排名。

```powershell
./rocketperf.exe run tests/fixtures/overexpanded.ini
$LASTEXITCODE
```

该例应退出4、stdout为空、stderr说明域限制。成功0；命令语法错误2；文件/格式/输出错误3；模型/求解拒绝4。不能把失败点填零或读成成功状态。

## 8 独立编译纯C源码包

需要Windows x64、GCC、CMake 3.19+和Ninja。构建只编译C和链接系统C/数学库；固定表已在源码中，不需运行数据生成器。

```powershell
cmake -S . -B build/cmake -G Ninja -DCMAKE_C_COMPILER=gcc -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=ON -DROCKETPERF_ENABLE_PYTHON_TESTS=OFF
cmake --build build/cmake
ctest --test-dir build/cmake --output-on-failure
./build/cmake/rocketperf.exe run cases/benchmarks/air_mach2_vacuum.ini
```

此方式执行五个C测试：core、thermo、combustion、cycle、adapters。完整私有仓库另有Python CLI/档案/运行管理测试和统一质量入口；它们用于验证和追溯，不参与发布程序的物理解算。

## 9 结果怎样核验

| 证据 | 检查内容 | 支持范围 |
|---|---|---|
| 解析参考 | 教学喷管、恒cp/恒密度部件极限 | 方程和数值实现 |
| 守恒/关系复算 | 元素、质量、焓、熵、声速、通量、几何、轴功计账 | 明确模型内自洽性 |
| CEA/Cantera/液体参考 | 同输入、同物性基准、相同冻结位置 | 同源或独立软件方法对照 |
| 错误输入/篡改 | 错单位/ID、非有限数、超域、预算耗尽、假成功 | 失败协议和证据完整性 |
| 发布包复跑 | 固定提交、二进制/ZIP哈希、纯C重建和隔离PATH运行 | 接收文件与程序行为 |

RP-1公共入口已有33次C运行和21张CEA卡，七组O/F=2.2/2.4/2.6/2.9/3.2/3.6/4.0包含HP及A10/A40。参考核验容差燃温0.02 K、物种摩尔分数2e−6、c*/有效速度0.03 m/s；这些是打印精度感知的软件容差，不是硬件测量误差。

富燃料O/F=0.5的九气相C/CEA曾失败；O/F=1时扩展产物出现凝聚碳，燃温差26.45 K。七个支持点的九气相/扩展温差0.22–0.50 K，仍不证明整个压力/组成范围或相态稳定性。

真实发动机实验、泵图谱、燃料批次、损失/冷却/瞬态和完整循环参考尚缺，软件PASS不能代替这些证据。公开参数、研究假设、求解结果必须分别讲明。

## 10 维护和组员讲解

完整仓库首先核对Git提交，读worknow与handoff，再用任务工具领取契约。改输入协议时维护适配器和CLI测试；改热化学时维护数据基准、库存、HP与独立参考；改喷管时核对能量/熵/通量和背压域；改循环时说明总消耗、支路去向和轴功/热交换口径。

推荐讲解顺序是两型构型与缺口、一个明确输入的C算例、模块调用、成功/拒绝输出、参考证据、改进收益与代价。接收者实际运行并记录确认与未确认内容，不只看截图。

原始资料按版本保留。修改源码或有效说明后须重跑相应检查并建立本地提交；生成视图由登记生成。新图应实际渲染检查，不能只凭生成命令成功。GitHub私有仓库保存完整维护历史，阶段Release固定某一提交；不同包不混用文件。
