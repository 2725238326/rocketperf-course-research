## 两种拓扑各自闭合什么

| 关系 | `staged_combustion=false`：发生器开式外排 | `staged_combustion=true`：全氧化剂富氧补燃情景 |
|---|---|---|
| 预燃/发生器 | 泵后燃料与氧化剂按给定O/F混合；Q=0 HP求温度 | 全部氧化剂与一部分燃料进富氧预燃室；Q=0 HP求温度 |
| 涡轮 | 按给定出口压力解冻结膨胀 | 以泵/辅助轴功需求为目标，夹逼求涡轮出口压力 |
| 质量分流 | 涡轮比功决定支路质量；各推进剂从主路扣除 | 全部氧化剂留在支路；预燃燃料按预燃O/F分配，剩余燃料进主室 |
| 主室入口 | 未分流的新鲜燃料与氧化剂 | 新鲜剩余燃料 + 涡轮出口全部回流气 |
| 元素与焓 | 主室/外排分别核对元素与焓流 | 回流由冻结组分换算C/H/O库存；回流焓和剩余燃料泵后焓混合后求主室HP |
| 支路去向 | 外排喷管，推力乘声明的轴向投影 | 返回主室；无独立外排喷管，不重复计质量或低位热值 |
| 压力条件 | 泵后压力须克服预燃室压力和声明压降 | 涡轮出口至少为主室压力加回流压降；轴功不可达则拒绝 |

两者均使用恒密度绝热泵、单轴、冻结涡轮/喷管、九种中性理想气相C/H/O物种的固定数据集，以及HP软件守卫1000–6000 K。代码不求冷却、泵图谱、启动瞬态、材料温度或寿命。煤油入口使用RP-1指定替代物和显式密度假设，不能当国产煤油批次。

## 和组员实现合并时逐项对照

拿到组员代码后保留原文件与来源，建立新对照记录，再比较下列项；只有物理定义一致时才合并实现，不能按函数名或输出数值接线。

1. **模式定义**：开式出口质量/动量控制体；补燃预燃室采用富氧还是富燃、哪股推进剂全流过涡轮、涡轮气体回到哪里。
2. **输入单位/含义**：总流量、主室和预燃室O/F定义、泵入口/出口压力、压降、焓基准、元素库存质量基准、效率定义。
3. **求解未知量**：开式支路分流与指定涡轮压力；补燃涡轮出口压力/分流与泵轴功闭合。核对可解条件、根区间和不可达状态。
4. **守恒边界**：每股物料只计一次；比较预燃室、涡轮、回流混合、主室、喷管的元素/焓/质量账；辅助功和机械损失保持同一约定。
5. **软件契约**：模型ID、有限值/范围、求解失败状态、输出事务性、JSON/文本字段及调用签名。
6. **验证向量**：解析泵/涡轮极限、零轴功、轴功不足、回流压力不可达、支路饥饿、质量/元素/总焓、同基准HP/CEA和篡改结果拒绝。
7. **限制与证据**：报告两份实现使用的同源或不同热化学数据、替代燃料、冻结位置、凝聚相、喷管分离和真实型号证据范围。

合并时优先留一个公共输入/结果类型和一个显式拓扑枚举或布尔入口；若组员版本有更准确方程或独立参考，先追加制造解/测试，再保留旧模型ID与向后兼容算例。最终由登记的模块源码、统一构建、质量入口和正式归档确定状态。
