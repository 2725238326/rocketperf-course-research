# RES-004：热化学与循环模型范围

## 研究问题

在公开型号参数不完整、核心计算必须为 C17 的条件下，首版大作业应做到哪一层热化学和发动机循环，哪些高保真内容应明确延期？本记录依据 `RES-001`、`RES-002`、`RES-003`、NASA RP-1311、本地开源项目快照和 2026-10-02 的限定检索形成。

## 已确认的循环证据

- 蓝箭官方TQ-15A报道写出其与TQ-12A共用“燃气发生器”等关键组件；LandSpace作者在2025 IAC摘要中直接把TQ-12A及真空型TQ-15A归为甲烷/液氧燃气发生器循环发动机。这个结论可用于天鹊家族架构情景，但没有公开发生器混合比、排气分流比例、泵功率图谱或遥二具体批次的完整性能卡。
- 西安航天动力研究所论文对YF-100写出富氧燃气发生器、富燃推力室补燃循环；中国载人航天官网转载的130吨级泵后摆论文写出“高压补燃”并以120吨级高压补燃发动机为基础。该证据支持YF-100/130吨级发动机家族的循环方法，但没有单独点名长十乙首飞子型的发动机后缀和验证数据。
- 因而，ZQ-3可建立“开式燃气发生器”方法情景，CZ-10B一级可建立“高压补燃家族”方法情景；两者都必须标为架构/条件性模型，不能改写成四个具体飞行对象的完整已识别循环。

## 首版选择

### 热化学

选择 L1 的**受限版本**，组分先限于可由公开NASA9数据和参考算例支撑的 C/H/O 气相物种；不处理电离、凝聚相和沉积碳。燃料方面：甲烷使用明确化学式；煤油不假装有唯一公开成分，必须建立一个带来源的替代物记录，或只在 L0/L1 的方法情景中使用已声明的代理燃料。

燃烧室先做定温定压平衡，再做定压绝热焓平衡求温度；喷管冻结位置固定为燃烧室出口。平衡/冻结两个结果必须共享同一输入和数据版本。若物种、焓基准或温区超出数据库范围，运行失败并报告原因，不能静默外推。

### 循环

选择 L2 的**零维稳态集总模型**，先只实现：

1. 总质量流量与支路分配；
2. 泵压升和轴功率；
3. 发生器/预燃室热状态输入或平衡状态；
4. 涡轮功率与轴机械效率；
5. 排气是否进入主喷管控制体；
6. 主室、涡轮排气和外排支路的推力/消耗边界。

首版不实现起动/关机瞬态、不从稳态结果推导真实深度节流范围、不计算具体冷却通道热流和重复使用寿命。这样既能回应课件“推力室与发动机的区别”，又不会用虚构泵图谱填补公开缺口。

## 控制体和守恒契约

系统必须同时输出：

```text
mass_residual = mdot_in - sum(mdot_out)
power_residual = turbine_power - (pump_power / eta_shaft + auxiliary_power)
thrust_boundary = chamber_exhaust + turbine_exhaust + other_declared_exhaust
```

冷却流若最终回到主室，只记一次总消耗；若外排则必须在质量残差和推力边界中同时出现。涡轮排气若并入喷管，只能在统一控制体中计一次；若作为损失排出，则不能又加进主喷管推力。每一项残差都要有绝对值、归一化值和容差。

## 数据需求和缺口处理

**必须有来源或显式假设的输入：** 推进剂/替代物组成、NASA9系数和温区、燃烧室压力、O/F、喷管面积比、泵/涡轮效率、压降、支路比例、排气边界、环境压力。

**当前公开缺口：** 四个具体飞行对象的室压、面积比、O/F定义、工况比冲；长十乙二级型号/台数/循环；具体泵图谱和涡轮效率。它们不得直接写入 `baseline.json` 的事实记录。研究算例必须使用独立 `assumption` 记录，包括范围、理由、来源、敏感性和模型ID。

## 验证顺序

1. L0 继续使用 C0 Mach 2 解析、守恒和失败路径。
2. L1 先验证单物种NASA9 `cp/h/s`、元素守恒和焓闭合，再和NASA CEA固定版本做少量对照。
3. L2 先验证人为构造的单支路/双支路质量和功率守恒，再验证极限情况：支路为零、泵功率为零、排气完全并入或完全外排。
4. 只有上述模块通过，才将架构情景与ZQ-3/CZ-10B公开构型事实关联；结果标题必须写明“架构情景/假设编号”。

## 对大作业设计的影响

- 主研究题建议冻结为“主室到整机：支路流量与排气利用如何改变系统性能”，它直接对应课程 P24 的边界提醒，且 L2 能给出质量/功率残差。
- 备用研究题为“喷管膨胀比在环境压力变化下的性能权衡”，即使L1/L2延期，L0也能可靠完成。
- C17 核心分成 `thermo`、`nozzle`、`cycle`、`study` 四个可独立验收模块；外部CEA/Pyskyfire只在 `tools/` 对照，不穿透业务接口。
- 若L1或L2在 2026-10-05 前没有可验证原型，交付降级为 L0 + 条件性系统模型，报告明确延期原因和未覆盖字段，不用外部软件输出冒充自有C结果。

## 结论

首版模型应该是“可验证的小而完整”：L0必交，L1争取实现，L2围绕守恒和边界实现；L3延期。这样既保留热化学和循环研究价值，又把数据、许可和验证风险控制在课程交付可承受范围内。
